# 算价规则与坑点（pricing-rules）

> 原则：**只写验证过的；没验证的明确标「待实测」，不写死假设。**
> 标注：✅ 已实测 ｜ ⬜ 待实测
> 最后更新：2026-10-10

---

## 1. 金额单位（最关键的坑）

| 来源 | 单位 | 状态 |
|---|---|---|
| `query-my-coupons` 的「优惠」 | **元**（实测返回如 `¥13.3`） | ✅ 实测 |
| `query-my-account` 积分数值 | 字符串整数（如 `"0"`），非金额 | ✅ 实测 |
| `calculate-price` 的价格字段 | **未知** | ⬜ 待实测 |

⚠️ **不要照搬方案里的「接口金额单位为分，展示前 ÷100」** —— 该假设未经实测，与券包实测（元）矛盾。

**处理约定**
- 本地账本（`ledger.py`）统一以**分（整数）**存储，避免浮点误差。
- 入库时用 `--unit` **显式声明来源单位**（`yuan` / `fen` / `unknown`），脚本不做假设。
- 同时保留原始值与原始单位（`raw_value` / `unit_source`）以便溯源。
- `calculate-price` 首次实测后，把真实单位补进本表，并把 `unit` 参数固定在链路上。

## 2. 算价的必传参数（缺一即失败）

`calculate-price` 需要**完整 JSON**，顶层必须带齐：

| 参数 | 来源 | 说明 |
|---|---|---|
| `storeCode` | `delivery-query-addresses` | 门店编码 |
| `beCode` | `delivery-query-addresses` | 业务实体编码 |
| `addressId` | `delivery-query-addresses` | 配送地址 ID |
| `items` | `query-meals` | **对象数组**，每项含餐品编码与数量 |

> 三元组（`storeCode` / `beCode` / `addressId`）**必须同时存在**。
> 缺任一，不要发起算价请求（会因参数不完整失败），先回 `delivery-query-addresses` 补齐。

## 3. 券的计价规则

- **「优惠」是「用券后价格」，不是面额** —— `query-my-coupons` 的 `¥13.3` 表示用券后花 13.3 元，而非省 13.3 元。
  - 想算「省了多少」需要同一餐品的**原价**做差：`立省 = 原价 − 用券后价格`。
- **门槛**：可领取券列表（`available-coupons`）**不返回面额与门槛**，只有标题 / 状态 / 图片；面额相关只能走 `query-my-coupons`。
- **渠道差异**：券可能带「到店专用」等标签，**外卖 / 到店**适用范围不同，比对前先确认标签。
- **有效期两段式**：`query-my-coupons` 的有效期含「日期区间 + 每日可用时段」两段，解析时拆开；`ledger` 用 `expire_at` 存结束时间、`daily_window` 存时段。

## 4. 组合试算策略

默认准备 2~3 套候选，逐套 `calculate-price` 后比价：

| 组合 | 说明 |
|---|---|
| A · 单点 | 不用券，作为基准线（提供「原价」） |
| B · 用券 | 直接对目标餐品使用最优券 |
| C · 用券 + 凑单 | 命中门槛时补一件小额餐品，看净值是否更优 |

**输出格式**（每条组合）：`原价 / 券后 / 实付 / 立省`，最后给出 Top3。

> 是否值得「凑单」，判定标准是 **净省额**（凑单后立省 − 凑单多花的钱）> 0，而不是「凑到门槛」本身。

---

## 5. 限流与批量调用

- 服务端限制 **600 次 / 分钟 / Token**。
- 批量试算、循环调用一律**串行**，调用间隔 **≥150ms**（`mcp_call.py` 已内置节流）。
- 多组合仍触发 `429` 时，**降级为单组合试算**，并在回复中说明降级原因。

## 6. 坑点清单（Gotchas）

1. **别写死 ÷100** —— 单位随工具而异，先看图再换算。
2. **「优惠」≠「面额」** —— 见 §3。
3. **`available-coupons` 给不了券 ID** —— 需要 ID / 面额请走 `query-my-coupons`。
4. **算价前必须齐三元组 + items** —— 见 §2。
5. **券有渠道限制** —— 「到店专用」的券不能用于外卖。
6. **有效期含每日时段** —— 别只看日期。
7. **积分字段是字符串** —— `availablePoint` 等是 `"0"` 而非数字 0，比较前先转 int。
8. **官方字段拼写原样保留** —— `currentMouthExpirePoint`（Mouth＝Month，官方如此），勿「纠正」。
