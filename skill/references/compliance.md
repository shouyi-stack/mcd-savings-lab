# 合规红线速查（compliance）

> 本文件是开发与发布前的**自查清单**，对齐 `CONTEST_DECLARATION.md` 与大赛活动规则。
> 任何一条越线，都可能直接导致**取消参赛 / 获奖资格**。动手前先看一眼。

---

## 一、内容红线（绝不能做）

| # | 红线 | 说明 |
|---|---|---|
| 1 | **跨品牌对比** | 只允许对比「通用省钱工具 vs 本项目」。**绝不提任何其他快餐 / 餐饮品牌**，不做价格、口味、份额等横向比较。 |
| 2 | **不当措辞** | 禁用「薅秃」「吃垮」「撸羊毛」「白嫖」等贬损、投机性表达；文案保持正面、理性、尊重品牌。 |
| 3 | **真实凭证** | 仓库 / 提交材料中**不得出现真实 Token、密钥、密码、账号凭证**；配置一律用环境变量占位符。 |
| 4 | **他人个人信息** | 不采集、不存储、不展示他人个人信息；`accountId`、手机号、真实地址等**一律脱敏或排除**。 |
| 5 | **敏感能力** | 不做代付、代登录、绕过风控、批量刷券等行为；不发布指向违规站点的外链。 |
| 6 | **诱导性内容** | 不含赌博、抽奖诱导分享、虚假承诺收益等内容。 |

---

## 二、产品行为约束

1. **不代替用户支付** —— 仅生成订单，**支付由用户本人完成**。
2. **写操作必须二次确认** —— `auto-bind-coupons`（领券）、`create-order`（下单）等写操作，先复述完整清单与金额，用户明确确认后才执行。
3. **营养信息仅作官方数据呈现** —— 不给出医疗、营养、减重等专业建议；涉及健康诉求时建议咨询专业人士。
4. **数据仅存本地** —— 消费数据落 `data/`（已 gitignore），**不上传、不外传**；日志与公开产物一律脱敏。
5. **价格与库存以官方为准** —— 输出仅供参考，餐品信息、价格、供应状态以麦当劳官方渠道实时结果为准。
6. **Token 只走环境变量** —— `MCD_MCP_TOKEN` 仅从环境变量读取，禁止写入文件、提交或日志。

## 三、免责与署名

- 项目**非麦当劳官方产品**，须在 README 顶部与产物中明确声明。
- `CONTEST_DECLARATION.md` 必须是**官方原文，一字不改**（含标题、条款、措辞）。
- 版权署名统一为 **守毅客栈**（README / LICENSE / 产物页脚）。

## 四、提交前自查 Checklist

发布 / 提交前逐条打勾：

- [ ] 全仓库无真实 Token / 密钥（`grep -rniE "Bearer [A-Za-z0-9._-]{20,}"` 无命中）
- [ ] 无他人个人信息（`accountId`、手机号、真实地址）
- [ ] 文案无跨品牌对比、无不当措辞
- [ ] `CONTEST_DECLARATION.md` 与官方原文一致
- [ ] README 含「非官方产品」免责声明
- [ ] 写操作均有二次确认提示
- [ ] 演示素材（截图 / GIF）已脱敏（无 Token、无手机号、无真实地址）
- [ ] `data/`、`.env`、`*.db` 已在 `.gitignore` 中

## 五、对齐的官方条款（来源：`CONTEST_DECLARATION.md`）

- **原创性**：项目系原创，或已获合法授权；不侵犯第三方知识产权、隐私权、商业秘密。
- **合规性**：不含违法、侵权、低俗、暴力、歧视、赌博内容；不含恶意代码、后门、钓鱼链接。
- **信息安全**：不含真实凭证与他人个人信息，配置仅用占位符。
- **规则遵守**：违反规则或不实声明，主办方有权取消资格与奖励。
